# model-benchmark

Стенд сравнения библиотечной и встроенной парадигм машинного обучения в браузере. Библиотечная часть использует **TensorFlow.js** и, для отдельных текстовых задач, **Transformers.js / ONNX Runtime Web**. Встроенная часть вызывает ИИ-API Chrome: Prompt, Summarizer, Rewriter, Writer, Proofreader, Translator и LanguageDetector в зависимости от эксперимента и доступности API.

Все экспериментальные модели исполняются на клиенте. FastAPI сохраняет измерения в PostgreSQL и обслуживает нашего агента через локальную Ollama. Translator и LanguageDetector обозначены в интерфейсе как встроенная парадигма, но используют собственные браузерные модели, а не обязательно Gemini Nano.

## Запуск и порты

Из корня проекта:

```sh
docker compose up -d --build
```

В Windows можно запустить `ЗАПУСТИТЬ.bat`, в Bash — `bash run.sh`. Они открывают адрес фронтенда с настроенным портом. Docker Desktop должен быть запущен.

В текущем локальном `.env` заданы:

```env
FRONTEND_PORT=18080
BACKEND_PORT=18000
VITE_API_BASE_URL=http://localhost:18000
CORS_ORIGINS=http://localhost:18080
```

| Сервис | Адрес на ноутбуке с текущим `.env` | Порт внутри контейнера |
|---|---|---|
| Интерфейс | http://localhost:18080 | 80 |
| API / Swagger | http://localhost:18000/docs | 8000 |
| Проверка БД и конфигурации API | http://localhost:18000/api/health | 8000 |
| Ollama | http://localhost:11434 | 11434 |

Без `.env` значения Compose по умолчанию: фронтенд **8080**, API **8000**, Ollama **11434**. Эти же значения находятся в [`.env.example`](.env.example). При настройке новых внешних портов согласуйте `VITE_API_BASE_URL` и `CORS_ORIGINS`, затем пересоберите фронтенд. Не заменяйте существующий `.env` примером, если хотите сохранить текущие порты.

Первый запуск скачивает модели Ollama; следить за загрузкой: `docker compose logs -f llm-bootstrap`. Готовность HTTP API не означает, что веса серверной модели уже скачаны. Эксперименты доступны независимо от готовности агента.

`docker compose down` сохраняет данные. `docker compose down -v` удаляет тома PostgreSQL и Ollama: измерения, рекомендации, историю чатов, индекс и серверные веса моделей. Браузерные кеши эта команда не очищает.

## Архитектура

| Компонент | Реализация | Документация |
|---|---|---|
| frontend | React 19, TypeScript 7, SCSS, Vite 8, nginx | [frontend](frontend/README.md) |
| backend | Python 3.12, FastAPI, SQLAlchemy 2, psycopg 3 | [backend](backend/README.md) |
| database | PostgreSQL 16, JSONB | [database](database/README.md) |
| llm | Ollama: `qwen3.5:4b` | [llm](llm/README.md) |
| checks | проверки адаптеров, RAG и интерфейса | [checks](checks/README.md) |

```text
Браузер: TF.js / Transformers.js + ONNX / встроенные API Chrome
    ├── измерения → FastAPI → PostgreSQL
    └── чат → FastAPI → инструменты чтения рекомендаций / измерений / статистики
                         └── наш planner → Ollama: выбор инструментов и поток ответа
```

Генерация ответов агента работает локально через Ollama. Установка зависимостей и первая загрузка весов требуют внешней сети: TF.js скачивает модели из CDN, Transformers.js — из Hugging Face, Chrome управляет загрузкой встроенных моделей, Ollama скачивает свои веса. [Локальный режим TF.js](frontend/public/models/README.md) переключает все шесть моделей TensorFlow.js на веса и словари из самого стенда.

## Эксперименты

Текущий реестр: [`frontend/src/benchmark/experiments.ts`](frontend/src/benchmark/experiments.ts). В нём 14 экспериментов.

| Ключ | Задача | Библиотечная модель / метод | Встроенный API |
|---|---|---|---|
| `text_classification` | Тональность текста | TF.js: USE и сравнение с опорными эмбеддингами | Prompt |
| `text_moderation` | Токсичность | TF.js: Toxicity, порог 75% | Prompt |
| `question_answering` | Вопрос по контексту | TF.js: MobileBERT QnA, извлечение ответа | Prompt |
| `image_classification` | Классификация изображения | TF.js: MobileNet v2 1.0 224 | Prompt с изображением |
| `object_detection` | Классы и количество объектов | TF.js: COCO-SSD MobileNet v2, порог 50%, до 20 объектов | Prompt с изображением, 80 классов COCO |
| `face_counting` | Количество лиц | TF.js: BlazeFace / MediaPipe Face Detector, до 20 лиц | Prompt с изображением |
| `tfjs_backends` | Влияние ускорителя | TF.js: MobileNet на WebGPU, WebGL, WASM, CPU | Не участвует |
| `text_summarization` | Суммаризация | TF.js: USE, выбор предложений исходного текста | Summarizer или Prompt |
| `semantic_search` | Выбор релевантного документа | TF.js: USE, косинусная близость | Prompt |
| `text_rewriting` | Перефразирование | ONNX: FLAN-T5 small | Rewriter или Prompt |
| `text_translation` | Перевод en ↔ ru | ONNX: OPUS-MT | Translator |
| `language_detection` | Определение языка | ONNX: XLM-RoBERTa language detection | LanguageDetector |
| `text_proofreading` | Исправление грамматики | ONNX: T5 Tiny GEC | Proofreader или Prompt |
| `text_generation` | Генерация по инструкции | ONNX: SmolLM2 360M Instruct, q8, WASM | Writer или Prompt |

Тональность через опорные эмбеддинги и экстрактивная суммаризация — библиотечные алгоритмы на готовом энкодере. Это не специализированная модель тональности и не генеративная суммаризация. Сравниваются разные способы решения общей задачи, а не одинаковые модели. Автоматической оценки качества всех ответов стенд не выполняет; генеративные модели могут повторяться и выдавать неверные факты.

`builtin_availability` сохраняется кнопкой «Записать в датасет» в панели среды. Это диагностика API, а не карточка эксперимента; отдельного блока для неё на вкладке «Измерения» нет. В общей CSV-выгрузке такие записи остаются.

## Интерфейс и измерения

На вкладке «Стенд» доступны среда прогона, статусы моделей, отдельные настройки каждой карточки и последовательный «Запустить все». Для TF.js выбираются доступные бэкенды, для ONNX — библиотечная модель целиком; выбор ускорителей TF.js к ONNX не применяется. Панель среды отслеживает загрузку Gemini Nano и показывает процент, когда Chrome предоставляет сведения о прогрессе. Загрузка встроенной модели или языкового пакета может потребовать действие пользователя.

Вопрос и контекст QnA вводятся отдельно. Семантический поиск использует запрос и до пяти документов A–E с названиями, сворачиваемыми полями и лимитом 250 символов текста на документ. Перевод поддерживает направления английский → русский и русский → английский с маской букв исходного языка. Генерация короткого текста ограничивает ввод английскими буквами, пробелами и пунктуацией.

| Метрика | Значение |
|---|---|
| `load_ms` | Загрузка / инициализация модели или создание сессии; для кешированной библиотечной модели — 0 |
| `first_token_ms` | До первого предсказания; при потоковом Prompt API — до первого фрагмента, без потокового замера — до готового ответа |
| `inference_ms` | Время обработки входа без загрузки |
| `total_ms` | Сумма `load_ms` и `inference_ms` |
| `memory_mb` | Изменение доступной JS-кучи; не полный объём RAM/VRAM модели |

По умолчанию сохраняются пять повторов каждой выбранной конфигурации. При включённом «Отбросить прогревочный прогон» выполняется дополнительный первый вызов, который не сохраняется. Чекбокс можно отключить. Запуск серии из неактивной вкладки блокируется. Каждый результат содержит характеристики среды, параметры модели и статус `ok`, `error` или `unsupported`.

«Измерения» показывает последние прогоны по пять строк на странице и статистику последних успешных записей (обычно окно 10). Для `tfjs_backends` используются отдельная таблица латентности и сводки по ускорителям. Статистика не разделяет версии модели автоматически: после замены модели в окне могут оказаться старые и новые записи. Выгрузка внутри карточки содержит все записи её эксперимента; общая кнопка — все эксперименты, включая диагностику. Текущие фильтры парадигмы/бэкенда CSV не ограничивают.

## Рекомендации и агент

Вкладка «Рекомендации» содержит статичную таблицу из БД и чат агента. Локальная модель `qwen3.5:4b` выбирает инструменты: список записанных экспериментов, чтение рекомендаций и прогонов, расчёт статистики, сравнение двух серий и построение графиков медиан. Инструменты читают актуальную БД; медианы и разброс считает Python отдельно по модели и бэкенду, только для успешных прогонов. Сравнение серий по умолчанию берёт две последние серии одного эксперимента. Прямой вопрос о таблице допускает только инструмент рекомендаций.

Агент выполняет только чтение: запуск экспериментов, изменение настроек и удаление данных не поддерживаются. Лимиты: четыре шага выбора инструментов, восемь вызовов; выборка прогонов до 50 строк, статистики до 500. Ограниченная выборка отмечается в источниках. Ответ без данных инструмента не допускается. Источники показывают результаты инструментов; `score=1` в совместимом API — служебное значение, не косинусная близость. Векторный поиск и эмбеддинги в чате больше не используются; маршрут переиндексации удалён, старые адреса чата временно принимаются тем же агентом.

Для явных запросов статистики и сравнения серий набор инструментов ограничивается соответствующим расчётом; модель выбирает эксперимент и фильтры. В общих вопросах доступны все инструменты. Несколько обращений к локальной модели могут занять больше времени, чем прежний один запрос RAG; агент не является автоматическим ускорением генерации.

Числовые отчёты формируются кодом, включая направление изменения латентности и фактическое число прогонов. Для свободных объяснений используется Ollama; Thinking передаётся отдельно от ответа. Расчёты и графики выполняет Python-код бэкенда, скиллы задают правила работы с данными.

История чата хранится в PostgreSQL, в браузере сохраняется идентификатор чата. Лимит — 30 завершённых пар вопрос/ответ, после чего нужно удалить историю для продолжения. Планировщик получает последние три пары для понимания уточняющих вопросов; итоговый ответ формируется только по новым результатам инструментов, без прежних ответов и чисел из истории. Thinking и удаление истории находятся в блоке ввода; рассуждения передаются отдельно от ответа.

## Настройки и команды

Все параметры Compose перечислены в [`.env.example`](.env.example). `VITE_*` подставляются при сборке. Модель агента задаётся `OLLAMA_CHAT_MODEL`, длина ответа — `AGENT_MAX_TOKENS`. Старое имя `RAG_MAX_TOKENS` временно принимается. Embedding-модель и параметры векторного поиска удалены.

```sh
make up
make down
make logs
make rebuild
make models
# Makefile не загружает .env для этой команды: укажите внешний порт API.
BACKEND_PORT=18000 make export-csv
```

Прямая выгрузка при текущих портах:

```sh
curl -o measurements.csv http://localhost:18000/api/measurements/export.csv
curl -o measurements_text_classification.csv "http://localhost:18000/api/measurements/export.csv?experiment_key=text_classification"
```

CSV использует `;`, UTF-8 и BOM. Колонки включают эксперимент, парадигму, модель, номер серии, статус, метрики, настройки, среду и дату.

Для встроенных API проверяйте фактическую доступность в вашем Chrome на localhost или другом безопасном контексте. Набор API, языков и модальностей зависит от сборки, устройства и установленных моделей. `Translator` и `LanguageDetector` проверяются отдельно от `LanguageModel`; наличие Prompt API не гарантирует их доступности.

```js
typeof LanguageModel !== 'undefined' && await LanguageModel.availability()
```

## Каталоги

- `frontend/` — интерфейс, браузерные модели и измерения.
- `backend/` — API, агент, его инструменты и история чатов.
- `database/` — начальная схема и рекомендации.
- `llm/` — bootstrap моделей Ollama.
- `checks/` — проверочные скрипты и инструкции.
- `scripts/` — загрузка локальных TF.js-весов и диагностика формата ответа агента.

Подробности запуска и сверки с инструментом TF.js: [ЗАПУСК.md](ЗАПУСК.md). Проверки: [checks/README.md](checks/README.md).

Инструкции по сценариям агента находятся в `backend/app/agent/skills/`, инструменты — в `tools/`. По запросу графика агент строит столбчатое сравнение медиан записанных измерений. Основной API — `/api/agent/*`, заголовок чата — `X-Agent-Chat`. История остаётся в существующей таблице `rag_chats`, чтобы сохранить прежние диалоги.
