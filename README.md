# model-benchmark — стенд сравнения подходов к интеграции ИИ в браузер

Экспериментальный стенд для НИР 3: сравнение **библиотечной** (TensorFlow.js) и
**встроенной** (Gemini Nano через Prompt API в Chrome) парадигм интеграции
машинного обучения в веб-приложения.

Приложение поднимается одной командой, снимает метрики в браузере, складывает их
в PostgreSQL и отвечает на вопросы через RAG-бота на локальной языковой модели.
Ни один сервис не обращается к внешним API.

## Быстрый старт

```bash
cp .env.example .env      # необязательно: без него подставятся значения по умолчанию
docker compose up -d --build
```

Через несколько минут (первый запуск качает модели для Ollama — около 3,2 ГБ):

| Адрес                        | Что там                          |
|------------------------------|----------------------------------|
| http://localhost:8080        | стенд                            |
| http://localhost:8000/docs   | интерактивная документация API   |
| http://localhost:8000/api/health | состояние сервисов           |

Прогресс загрузки моделей: `docker compose logs -f llm-bootstrap`.

Остановить: `docker compose down`. Стереть базу и скачанные модели: `docker compose down -v`.

## Где происходят вычисления

Ключевая особенность архитектуры, которая объясняет, почему бэкенд выглядит
скромно. Обе сравниваемые парадигмы исполняются **в браузере пользователя**:
TensorFlow.js загружает веса и считает инференс на WebGL, WebGPU или
WebAssembly, а Gemini Nano вообще живёт внутри Chrome и наружу не выходит.
Сервер физически не может выполнить ни тот, ни другой инференс, поэтому его
роль — принять готовые числа, сохранить их, посчитать статистику и обслужить
RAG-бота.

```
┌─ Браузер (Chrome) ────────────────────────┐
│  TensorFlow.js ──┐                        │
│                  ├─► замеры performance   │
│  Gemini Nano ────┘        │               │
└───────────────────────────┼───────────────┘
                            │ POST /api/measurements
┌─ Docker ───────────────────┼───────────────┐
│  backend (FastAPI) ────────┴──► database   │
│       │                         (PostgreSQL)│
│       └──► llm (Ollama) ──► ответы RAG-бота │
└─────────────────────────────────────────────┘
```

## Эксперименты

| Ключ                   | Задача                                   | Парадигмы                |
|------------------------|------------------------------------------|--------------------------|
| `text_classification`  | тональность короткого текста             | обе                      |
| `image_classification` | классификация изображения                | обе                      |
| `object_detection`     | обнаружение объектов: COCO-SSD и Gemini Nano | обе при поддержке изображений в Prompt API |
| `face_counting`        | подсчёт лиц: BlazeFace через TF.js и Gemini Nano | обе при поддержке изображений в Prompt API |
| `tfjs_backends`        | тот же инференс на WebGPU, WebGL, WebAssembly и CPU | только TensorFlow.js |
| `builtin_availability` | какие встроенные ИИ-API объявлены и работают | только встроенная   |

Третий эксперимент существует потому, что Prompt API не даёт разработчику
выбрать ускоритель. Сравнивать тут нечего — и это самостоятельный вывод
о встроенной парадигме, а не пробел в методике.

Четвёртый снимается кнопкой «Записать в датасет» на панели среды и пишет по
строке на каждый встроенный API: объявлен ли он и что отвечает
`availability()`. На устройстве, не проходящем аппаратный порог, Chrome не
объявляет часть объектов вовсе — применимость встроенной парадигмы упирается
не в скорость, а в наличие модели на конкретной машине, и это надо измерять
наравне с латентностью.

### Как снимаются метрики

| Метрика           | Что означает                                                        |
|-------------------|---------------------------------------------------------------------|
| `load_ms`         | загрузка и инициализация модели; у Gemini Nano — создание сессии      |
| `first_token_ms`  | время до первого предсказания (у Nano — первый фрагмент потока)       |
| `inference_ms`    | чистая латентность инференса без загрузки                             |
| `total_ms`        | `load_ms + inference_ms`                                              |
| `memory_mb`       | прирост занятой JS-кучи за прогон                                     |

Каждый эксперимент прогоняется серией. Первый запуск отбрасывается: он
компилирует шейдеры и всегда выпадает из общей картины. По остальным считаются
медиана, среднее, минимум, максимум и стандартное отклонение — медиана
устойчивее к единичным выбросам, поэтому в сравнительных таблицах опора на неё.

### Вкладка должна быть активной

Стенд отказывается запускать серию, если вкладка в фоне, и объясняет причину.
Ограничение выяснилось на практике: при неактивной вкладке Chrome душит
рендеринг, и прогон MobileNet на бэкенде WebGL не завершается за минуты, тогда
как WebGPU в тех же условиях считает нормально. Числа, снятые в этих двух
режимах, несопоставимы, поэтому состояние вкладки пишется в описание среды
каждого измерения, а запуск в фоне блокируется.

Вместе с состоянием вкладки в каждом измерении сохраняются версия Chrome,
модель видеоадаптера и адаптер WebGPU. Без них сравнивать прогоны с разных
машин бессмысленно, а для встроенной парадигмы именно видеоадаптер решает,
запустится ли она вообще.

## Требования к машине

Библиотечная часть работает в любом современном браузере. Встроенная требует:

- **Chrome 148 или новее.** На вебе Prompt API стабилен с этой версии и живёт в
  глобальном объекте `LanguageModel`. Флаги больше не нужны — они требовались,
  пока API оставался экспериментальным. В расширениях API доступен с Chrome 138,
  в сборках до 138-й он лежал в `window.ai.languageModel`; адаптер понимает и эту форму.
- **22 ГБ свободного места на диске** под веса модели.
- **Видеокарта с более чем 4 ГБ видеопамяти** либо, как запасной путь,
  **16 ГБ оперативной памяти и не менее четырёх ядер** процессора.
- ОС: Windows 10 или 11, macOS 13 и новее, Linux, ChromeOS на Chromebook Plus.
- Первая загрузка весов требует безлимитного подключения; дальше сеть не нужна.

Проверка в консоли браузера:

```js
await LanguageModel.availability()   // ожидаем 'available'
```

Если модель недоступна, стенд всё равно работает: прогоны Gemini Nano
записываются со статусом `unsupported` и текстом причины, а эксперимент
`tfjs_backends` даёт полноценные данные по библиотечной парадигме.

### Язык входных данных

Prompt API принимает `en`, `ja`, `es`, `de` и `fr`. Русского среди них нет: на
русский вход браузер отвечает `NotSupportedError`. Поэтому сравнительные
прогоны идут на английском тексте — иначе сравнивались бы не парадигмы, а
наличие языка в списке поддерживаемых. Universal Sentence Encoder на стороне
TensorFlow.js тоже обучен на английском, так что обе парадигмы получают
равные условия.

Русский текст в поле ввода не запрещён. Встроенная парадигма вернёт отказ, он
запишется статусом `unsupported` — и это самостоятельное наблюдение, важное
для любого русскоязычного веб-приложения.

Параметры `temperature` и `topK` на вебе недоступны, их отдали только
расширениям. Сессия создаётся со значениями модели по умолчанию, и это
записано в настройках каждого прогона.

## Независимая сверка

Числа стенда сверяются с официальным инструментом TensorFlow.js:
<https://tensorflow.github.io/tfjs/e2e/benchmarks/local-benchmark/>. Там есть те же
модели (MobileNetV2 с архитектурой 100 и Universal Sentence Encoder) и те же четыре
бэкенда. Пошаговый порядок сверки — в [ЗАПУСК.md](ЗАПУСК.md).

## Получение датасета для главы

```bash
make export-csv      # или напрямую:
curl -o measurements.csv http://localhost:8000/api/measurements/export.csv
```

CSV с разделителем `;` и BOM — открывается в Excel без плясок с кодировкой.
Колонки: ключ эксперимента, парадигма, модель, номер серии, статус, все пять
метрик, настройки прогона и среда.

## Настройка

Всё через `.env`, полный список — в [`.env.example`](.env.example). Чаще всего
меняют:

- `VITE_MODEL_SOURCE=local` — брать веса TensorFlow.js из `frontend/public/models`
  вместо CDN. Так сетевая задержка перестаёт попадать в `load_ms`, что для
  чистоты эксперимента лучше. Сначала выполните `make models`.
- `OLLAMA_CHAT_MODEL` — модель RAG-бота. По умолчанию `qwen3:4b`: помещается
  в 4 ГБ оперативной памяти и уверенно отвечает по-русски.
- `RAG_RECENT_MEASUREMENTS` — сколько последних измерений бот держит в контексте.

## Команды

```bash
make up          # поднять стенд
make down        # остановить, данные сохранить
make reset       # остановить и стереть базу и модели
make logs        # логи всех сервисов
make models      # скачать веса TensorFlow.js локально
make export-csv  # выгрузить датасет
```
