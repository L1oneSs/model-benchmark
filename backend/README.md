# backend — хранение измерений и RAG-бот

Чат поддерживает потоковый ответ: `POST /api/rag/ask?stream=true` возвращает
NDJSON-события `status`, `sources`, `thinking`, `token`, `done` (с итоговым `result`) или
`error`. Без параметра `stream` сохраняется обычный JSON-ответ.
Отключение клиента закрывает запрос к Ollama.

`RAG_MAX_TOKENS` ограничивает длину генерации (по умолчанию 384), а
`OLLAMA_KEEP_ALIVE` задаёт удержание чат-модели в памяти после запроса (по умолчанию 0 — выгружать).
Эмбеддинг-модель также выгружается после запроса. Ollama ограничена одной моделью,
одним параллельным запросом, четырьмя ядрами и 5 ГБ памяти без swap.
Первый запрос по-прежнему требует загрузки модели и обработки контекста.
В логах бэкенда записываются время поиска, загрузки модели и общее время ответа.
Переиндексация вычисляет эмбеддинги только для новых или изменённых документов.

Прямые вопросы о таблице рекомендаций читают её актуальные строки из PostgreSQL,
без подмешивания измерений и предыдущих ответов. Критерии ранжируются по словам
заголовка. Общий векторный поиск резервирует часть контекста под рекомендации;
тип каждого источника явно указан в промпте. Вопросы, явно сравнивающие таблицу
с измерениями, используют смешанный контекст.

Тело запроса поддерживает `thinking` (по умолчанию false). История берётся из PostgreSQL;
в контекст попадают последние три пары. Ответ извлекается
из структурированного JSON, рассуждения передаются отдельно. При исчерпании
бюджета thinking без ответа выполняется дополнительный проход без thinking.
История хранится в таблице `rag_chats`, которая создаётся при старте бэкенда.
Лимит — 30 завершённых пар вопрос/ответ. После достижения лимита `/ask` возвращает
409 до запуска модели; интерфейс предлагает удалить чат. Сохранение завершённого
ответа происходит до отправки события `done`. Ошибки и отменённые ответы не занимают лимит.
`GET /api/rag/history` читает историю, `DELETE /api/rag/history` очищает её и
аннулирует текущую генерацию. Запросы используют заголовок `X-Rag-Chat` с UUID.
В браузере хранится только этот идентификатор: истории разных профилей независимы.
Это идентификатор доступа локального стенда, не система учётных записей.
Прежняя история localStorage переносится при открытии чата через `/history/import`.
Импорт не перезаписывает непустую историю сервера. Данные PostgreSQL сохраняются в Docker-томе.

Проверки потока: `python -m unittest discover -s tests` из каталога `backend`
с установленными зависимостями. Скрипт `scripts/check-rag-stream.py` измеряет
задержки HTTP-потока при запуске внутри контейнера бэкенда.

FastAPI на Python 3.12, SQLAlchemy 2.0, драйвер psycopg 3.

## Что делает и чего не делает

Бэкенд **не выполняет инференс**. Обе сравниваемые парадигмы работают в
браузере: TensorFlow.js считает на WebGL, WebGPU или WebAssembly внутри
вкладки, Gemini Nano вообще встроен в Chrome и наружу не выходит. Сервер
физически не имеет к ним доступа.

Его задачи: принять готовые числа от фронтенда, сохранить, посчитать
статистику по сериям и обслужить RAG-бота.

## API

| Метод  | Путь                              | Назначение                                  |
|--------|-----------------------------------|---------------------------------------------|
| POST   | `/api/measurements`               | записать серию прогонов                     |
| GET    | `/api/measurements`               | постраничный список с фильтрами             |
| GET    | `/api/measurements/latest`        | последний прогон каждой парадигмы           |
| GET    | `/api/measurements/summary`       | медиана, среднее, разброс по серии          |
| GET    | `/api/measurements/export.csv`    | датасет для экспериментальной главы         |
| GET    | `/api/recommendations`            | таблица рекомендаций                        |
| PATCH  | `/api/recommendations/{rec_key}`  | уточнить вердикт по итогам измерений        |

| GET    | `/api/health`                     | состояние базы и имена моделей              |

## Статистика по сериям

`MeasurementRepository.aggregate()` считает по последним `window` удачным
прогонам медиану, среднее, минимум, максимум и стандартное отклонение каждой
метрики. В сравнительных таблицах опора на медиану: она устойчивее среднего к
единичным выбросам, которые на браузерных замерах неизбежны.

## Как работает RAG-бот

1. После каждой записи измерений запускается фоновая переиндексация. Она берёт
   все рекомендации и последние `RAG_RECENT_MEASUREMENTS` измерений, превращает
   каждую строку в человекочитаемый фрагмент и просит у Ollama вектор.
2. На вопрос пользователя считается вектор запроса, дальше косинусная близость
   ко всем фрагментам и отбор `RAG_TOP_K` лучших.
3. Фрагменты уходят в промпт локальной модели вместе с инструкцией отвечать
   строго по контексту и не выдумывать метрик.

Векторы лежат в `jsonb`, близость считается numpy прямо в процессе. Корпус
стенда — несколько десятков строк, полный перебор здесь дешевле любого
векторного индекса и не требует расширения pgvector.

Переиндексация вынесена в фон намеренно: запись измерений не должна зависеть от
доступности языковой модели. Если Ollama лежит, прогоны всё равно сохранятся,
в лог уйдёт предупреждение, а бот честно скажет, что индекс пуст и почему.
