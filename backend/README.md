# backend — API, хранение и RAG

Python 3.12, FastAPI, SQLAlchemy 2, psycopg 3. Экспериментальные модели TF.js, ONNX и встроенные API Chrome исполняет браузер. Сервер принимает их результаты, считает статистику и выполняет RAG-поиск и генерацию через Ollama.

## Структура

- `app/main.py` — FastAPI, CORS, роутеры и создание таблицы `rag_chats` при старте.
- `app/config.py` — конфигурация из окружения.
- `app/schemas.py` — схемы запросов, измерений, ответов и истории.
- `app/api/measurements.py` — запись, список, последний результат, статистика, CSV.
- `app/api/recommendations.py` — чтение и изменение вердиктов.
- `app/api/rag.py` — чат, NDJSON, история, импорт и переиндексация.
- `app/db/` — подключение, ORM четырёх таблиц и репозитории.
- `app/rag/retriever.py`, `embeddings.py` — поиск и векторизация.
- `app/rag/service.py`, `prompts.py` — генерация и отделение ответа от thinking.
- `app/rag/history.py` — история, ограничение количества ответов и блокировка конкурентных запросов.

## Порты

API слушает **8000 внутри контейнера**. В текущем `.env` Docker публикует его на **18000** ноутбука: http://localhost:18000/docs. Без настройки `BACKEND_PORT` внешний порт тоже 8000. Между контейнерами используются имена сервисов: PostgreSQL — `database:5432`, Ollama — `llm:11434`.

`/api/health` проверяет подключение к БД и возвращает имена настроенных моделей. Он не проверяет, что Ollama уже скачала веса или способна генерировать ответ.

## API

| Метод | Путь | Назначение |
|---|---|---|
| POST | `/api/measurements` | Сохранить пакет прогонов; назначить номер серии |
| GET | `/api/measurements` | Пагинация, фильтры эксперимента, подхода и бэкенда, сортировка |
| GET | `/api/measurements/latest?experiment_key=…` | Последний успешный результат каждого подхода |
| GET | `/api/measurements/summary?experiment_key=…` | Статистика последних успешных записей |
| GET | `/api/measurements/export.csv` | Весь датасет; `experiment_key` ограничивает эксперимент |
| GET | `/api/recommendations` | Актуальная статичная таблица |
| PATCH | `/api/recommendations/{rec_key}` | Изменить поля рекомендации |
| POST | `/api/rag/ask` | Ответ бота; `?stream=true` включает NDJSON |
| GET | `/api/rag/history` | История и лимит чата |
| DELETE | `/api/rag/history` | Очистить историю и аннулировать сохранение текущего ответа |
| POST | `/api/rag/history/import` | Импорт прежней клиентской истории в пустой чат |
| POST | `/api/rag/reindex` | Ручное обновление поискового индекса |

Схемы и полный набор параметров: Swagger `/docs`. Статусы измерений: `ok`, `error`, `unsupported`. В БД доступны два ключа подходов: `tensorflow_js` и `gemini_nano`; ONNX также хранится под библиотечным ключом `tensorflow_js`, конкретную модель определяют `model_name` и `settings`.

Сводка по умолчанию использует последние 10 успешных строк каждого подхода; возвращает медиану, среднее, минимум, максимум, стандартное отклонение и количество числовых значений каждой метрики. Параметры `window` и `backend` уточняют выборку. Номер серии и версия модели не образуют отдельные группы, поэтому после замены модели окно может смешивать старые и новые результаты. Неизвестные метрики не превращаются сервером в ноль.

CSV с UTF-8 BOM и разделителем `;` содержит метрики, настройки, среду и дату. Фильтрация экспорта ограничивается `experiment_key`.

## RAG-поиск

После сохранения измерений запускается фоновая переиндексация: все рекомендации и последние `RAG_RECENT_MEASUREMENTS` строк измерений превращаются в документы. Эмбеддинги вычисляются только для новых/изменённых документов. Индекс хранится в JSONB; косинусная близость считается numpy. При обновлении старые документы автоматически не удаляются, поэтому индекс может со временем содержать больше строк, чем текущее окно.

Прямой вопрос о таблице рекомендаций читает актуальные строки из PostgreSQL и ранжирует по словам заголовка, без измерений и предыдущей истории в контексте. Остальные вопросы используют векторный поиск, который резервирует часть результатов под рекомендации. Вопросы сравнения таблицы с измерениями используют смешанный контекст. Тип и ключ источника возвращаются вместе с ответом.

Недоступность Ollama не препятствует сохранению экспериментальных результатов. Ошибка фонового индексирования попадает в логи; ручная переиндексация доступна через API. Изменение рекомендации через PATCH само по себе не запускает фоновую переиндексацию; для обновления её векторного представления вызовите `/api/rag/reindex`.

## Поток, thinking и история

Тело `/ask`: `question` и `thinking` (по умолчанию false). История берётся с сервера, в контекст попадают последние три пары вопрос/ответ. `stream=true` возвращает NDJSON-события `status`, `sources`, `thinking`, `token`, `done` с `result` или `error`. Бэкенд запрашивает структурированный JSON-ответ Ollama и извлекает текст ответа отдельно от рассуждений. Если thinking исчерпал бюджет без ответа, выполняется дополнительный проход без thinking.

`RAG_MAX_TOKENS` — базовый бюджет ответа (384 по умолчанию); при thinking добавляется бюджет 512 токенов. Контекст Ollama настроен на 4096 токенов, вычисления — четыре потока. Таймаут Ollama в конфигурации — 180 секунд. Чат-модель удерживается согласно `OLLAMA_KEEP_ALIVE` (по умолчанию 0); модель эмбеддингов тоже выгружается после использования. Эти параметры влияют на холодный старт следующего запроса.

Чаты идентифицируются UUID в `X-Rag-Chat`. Это идентификатор доступа локального стенда, не аутентификация. Таблица `rag_chats` хранит завершённые ответы, thinking и источники. Лимит — **30 пар вопрос/ответ**, то есть до 60 пользовательских/ботовых сообщений. При исчерпании лимита или уже выполняющемся запросе `/ask` возвращает 409 до новой генерации.

Короткие блокировки строк защищают запись истории. Завершённый ответ сохраняется до события `done`; ошибка/отмена не занимает лимит. Удаление истории очищает маркер текущей генерации, чтобы её ответ не записался в удалённый чат. Импорт не перезаписывает непустую историю. Браузер хранит UUID, а история переживает перезапуск контейнера благодаря тому PostgreSQL.

## Проверки и разработка

Из `backend` с установленными зависимостями:

```sh
pip install -r requirements.txt
python -m unittest discover -s tests
```

Проверки реального API и браузерных адаптеров: [../checks/README.md](../checks/README.md). Python-чекеры используют внутренний адрес `http://localhost:8000`, поэтому запускаются внутри backend-контейнера.

Для запуска API вне Docker настройте `DATABASE_URL` на доступную PostgreSQL и `OLLAMA_URL` на доступную Ollama, а также `CORS_ORIGINS` под адрес фронтенда, затем выполните:

```sh
uvicorn app.main:app --reload --port 18000
```

В Compose PostgreSQL не опубликована на порту ноутбука; для такого режима потребуется отдельная БД или явная публикация её порта. Изменения схемы основных таблиц не применяются автоматически повторным запуском `init.sql`; `rag_chats` создаётся отдельно при старте API.
