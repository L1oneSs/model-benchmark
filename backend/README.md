# backend — API, хранение и агент

Python 3.12, FastAPI, SQLAlchemy 2, psycopg 3. Экспериментальные модели TF.js, ONNX и встроенные API Chrome исполняет браузер. Сервер принимает их результаты, считает статистику и выполняет инструменты нашего агента; генерация работает локально через Ollama.

## Структура

- `app/main.py` — FastAPI, CORS, роутеры и создание таблицы `rag_chats` при старте.
- `app/config.py` — конфигурация из окружения.
- `app/schemas.py` — схемы запросов, измерений, ответов и истории.
- `app/api/measurements.py` — запись, список, последний результат, статистика, CSV.
- `app/api/recommendations.py` — чтение и изменение вердиктов.
- `app/api/agent.py` — чат, NDJSON, история и импорт.
- `app/db/` — подключение, ORM трёх таблиц и репозитории.
- `app/agent/planner.py`, `tools/` — выбор инструментов Ollama и ограниченные запросы к БД.
- `app/agent/skills/` — загружаемые инструкции по сценариям; `tools/` — реестр и отдельные реализации инструментов.
- `app/agent/service.py`, `prompts.py` — генерация и отделение ответа от thinking.
- `app/agent/history.py` — история, ограничение количества ответов и блокировка конкурентных запросов.

## Порты

API слушает **8000 внутри контейнера**. В текущем `.env` Docker публикует его на **18000** ноутбука: http://localhost:18000/docs. Без настройки `BACKEND_PORT` внешний порт тоже 8000. Между контейнерами используются имена сервисов: PostgreSQL — `database:5432`, Ollama — `llm:11434`.

`/api/health` проверяет подключение к БД и возвращает имена настроенных моделей. Он не проверяет, что Ollama уже скачала веса или способна генерировать ответ.

## API

| Метод | Путь | Назначение |
|---|---|---|
| POST | `/api/measurements` | Сохранить пакет прогонов; назначить номер серии |
| GET | `/api/measurements` | Пагинация, фильтры эксперимента, подхода и бэкенда, сортировка |
| GET | `/api/measurements/latest?experiment_key=…` | Последний успешный результат каждого подхода |
| GET | `/api/measurements/summary?experiment_key=…` | Статистика последних успешных записей |
| GET | `/api/measurements/export.csv` | Весь датасет; `experiment_key` ограничивает эксперимент |
| GET | `/api/recommendations` | Актуальная статичная таблица |
| PATCH | `/api/recommendations/{rec_key}` | Изменить поля рекомендации |
| POST | `/api/agent/ask` | Ответ бота; `?stream=true` включает NDJSON |
| GET | `/api/agent/history` | История и лимит чата |
| DELETE | `/api/agent/history` | Очистить историю и аннулировать сохранение текущего ответа |
| POST | `/api/agent/history/import` | Импорт прежней клиентской истории в пустой чат |


Схемы и полный набор параметров: Swagger `/docs`. Статусы измерений: `ok`, `error`, `unsupported`. В БД доступны два ключа подходов: `tensorflow_js` и `gemini_nano`; ONNX также хранится под библиотечным ключом `tensorflow_js`, конкретную модель определяют `model_name` и `settings`.

Сводка по умолчанию использует последние 10 успешных строк каждого подхода; возвращает медиану, среднее, минимум, максимум, стандартное отклонение и количество числовых значений каждой метрики. Параметры `window` и `backend` уточняют выборку. Номер серии и версия модели не образуют отдельные группы, поэтому после замены модели окно может смешивать старые и новые результаты. Неизвестные метрики не превращаются сервером в ноль.

CSV с UTF-8 BOM и разделителем `;` содержит метрики, настройки, среду и дату. Фильтрация экспорта ограничивается `experiment_key`.

## Агент с инструментами

`qwen3.5:4b` выбирает функции в структурированном JSON-плане; Ollama ограничивает формат через JSON Schema. Backend проверяет и выполняет план, возвращает результаты модели и позволяет выбрать следующий шаг. `list_experiments` перечисляет записанные эксперименты; `read_recommendations` читает текущую таблицу; `read_measurements` выбирает отдельные прогоны; `calculate_statistics` считает медианы и выборочное стандартное отклонение; `compare_series` сравнивает одинаковые группы двух серий. Статистика учитывает только `status=ok`, группирует по подходу, модели и бэкенду; пропущенные метрики не заменяются нулём. По умолчанию сравниваются две последние серии.

Аргументы проверяет Pydantic; SQL строится параметризованными запросами SQLAlchemy. Инструментов записи, произвольного SQL и выполнения кода нет. Лимиты: четыре шага модели, восемь вызовов; отдельные прогоны до 50 строк, статистика до 500. Ограничение выборки передаётся как `truncated`; результаты более 8000 символов возвращают ошибку с просьбой сузить запрос. Если модель не вызвала инструмент успешно, ответ по памяти не допускается. Для прямых вопросов о таблице доступен только `read_recommendations`.

После сбора данных свободное объяснение формируется отдельным запросом к Ollama. Явные запросы медиан и сравнения серий формируют числовой отчёт через `app/agent/reports.py`: значения, количество samples, разница и направление изменения латентности выводятся кодом, без повторной интерпретации моделью. В этом режиме thinking не генерируется; поток и история сохраняются как обычно. `score=1` для источников инструментов — совместимое служебное поле, не релевантность векторного поиска. Сохранение измерений не запускает индексирование, а изменение рекомендации сразу видно агенту. Векторный поиск, эмбеддинги и `/api/rag/reindex` удалены. Старые адреса чата `/api/rag/ask` и `/api/rag/history` временно перенаправлены на тот же агент и скрыты из Swagger.

Для явных запросов медианы/статистики разрешён только `calculate_statistics`, для сравнения серий — `compare_series`: модель не может подменить расчёт пересказом отдельных прогонов. Ключи записанных экспериментов предварительно читаются как метаданные. Запрос на основе таблицы и измерений требует успешного получения результатов `read_recommendations` и `calculate_statistics`, даже без слова «сравни». Для остальных общих вопросов модель выбирает из полного набора инструментов. Флаг `complete` завершает план только после получения обязательных источников. Контекст результатов ограничен 12000 символами суммарно.

## Поток, thinking и история

Тело `/ask`: `question` и `thinking` (по умолчанию false). История берётся с сервера: последние три пары вопрос/ответ передаются планировщику, текст каждой реплики ограничен 600 символами. Итоговая генерация получает только текущий вопрос и новые результаты инструментов; старые ответы не служат источником чисел. `stream=true` возвращает NDJSON-события `status`, `sources`, `thinking`, `token`, `done` с `result` или `error`. Бэкенд запрашивает структурированный JSON-ответ Ollama и извлекает текст ответа отдельно от рассуждений. Если thinking исчерпал бюджет без ответа, выполняется дополнительный проход без thinking.

`AGENT_MAX_TOKENS` — базовый бюджет ответа (384 по умолчанию); при thinking добавляется бюджет 512 токенов. Контекст Ollama настроен на 8192 токена, вычисления — четыре потока. Таймаут Ollama в конфигурации — 180 секунд. Чат-модель удерживается согласно `OLLAMA_KEEP_ALIVE` (по умолчанию 0); при выборе инструментов thinking выключен; пользовательский Thinking применяется к итоговому ответу. Эти параметры влияют на холодный старт следующего запроса.

Чаты идентифицируются UUID в `X-Agent-Chat`. Это идентификатор доступа локального стенда, не аутентификация. Таблица `rag_chats` хранит завершённые ответы, thinking и источники. Лимит — **30 пар вопрос/ответ**, то есть до 60 пользовательских/ботовых сообщений. При исчерпании лимита или уже выполняющемся запросе `/ask` возвращает 409 до новой генерации.

Короткие блокировки строк защищают запись истории. Завершённый ответ сохраняется до события `done`; ошибка/отмена не занимает лимит. Удаление истории очищает маркер текущей генерации, чтобы её ответ не записался в удалённый чат. Импорт не перезаписывает непустую историю. Браузер хранит UUID, а история переживает перезапуск контейнера благодаря тому PostgreSQL.

## Проверки и разработка

Из `backend` с установленными зависимостями:

```sh
pip install -r requirements.txt
python -m unittest discover -s tests
```

Проверки реального API и браузерных адаптеров: [../checks/README.md](../checks/README.md). Python-чекеры используют внутренний адрес `http://localhost:8000`, поэтому запускаются внутри backend-контейнера.

Для запуска API вне Docker настройте `DATABASE_URL` на доступную PostgreSQL и `OLLAMA_URL` на доступную Ollama, а также `CORS_ORIGINS` под адрес фронтенда, затем выполните:

```sh
uvicorn app.main:app --reload --port 18000
```

В Compose PostgreSQL не опубликована на порту ноутбука; для такого режима потребуется отдельная БД или явная публикация её порта. Изменения схемы основных таблиц не применяются автоматически повторным запуском `init.sql`; `rag_chats` создаётся отдельно при старте API.

Структура агента и сценарии: [app/agent/README.md](app/agent/README.md). `build_chart` строит графики медиан или средних по моделям/бэкендам: HTML/CSS в чате, PNG через Matplotlib или интерактивный HTML через Plotly. Файлы Python-графиков сохраняются в `artifacts/agent-charts`, ссылки и данные — в истории. Инструкции из `skills/*.md` подгружаются планировщиком; произвольный код модели не исполняется.
