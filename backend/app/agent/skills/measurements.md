# Recorded measurements: измерения и статистика

## 1. Назначение и режимы

Выбирай режим по цели вопроса: просмотр конкретных результатов, агрегирование
метрик либо проверка уже рассчитанного значения. Эти режимы используют разные
инструменты и не должны подменять друг друга.

## 2. Обязательный протокол выполнения

<!-- runtime:start -->
Используй read_measurements для отдельных выходов, настроек и ошибок;
calculate_statistics для агрегатов; explain_statistic для формулы и исходных
замеров. Ключ разрешай по list_experiments/каталогу, не угадывай.

Передай только запрошенные approach, backend, model_name, run_index.
«По всем моделям и бэкендам» не сужай до одной группы.
Без run_index выборка последних строк может включать несколько серий.
limit ограничивает число строк глобально, а не отдельно каждую группу.

Статистика включает только успешные прогоны и конечные числовые значения,
отдельно по approach/model/backend. n=samples — число значений конкретной метрики,
runs — число строк группы; они могут различаться. Не рассчитывай агрегаты сам.
Медиана — центральное значение; mean — среднее; stdev — выборочное стандартное
отклонение, не погрешность или доверительный интервал. P95 и значимость не предоставлены.

Время — мс. memory_mb — разница JS heap, не общая память модели/GPU/системы.
Ноль является значением, отсутствие — пропуском. Отрицательная память допустима.
При truncated сообщи об ограниченной выборке; не называй limit фактическим n.

Для объяснения формулы используй сохранённые measurement_ids и перечитай БД.
Покажи отсортированные значения, ID, серии, n и формулу median/mean.
Если в старой истории нет ID, обозначь проверку текущей выборки.
Если расчёт не восстановлен, не утверждай, что записей нет вообще.

## 3. Инструменты и параметры

| Инструмент | Назначение | Предел выборки |
|---|---|---|
| `read_measurements` | Отдельные строки и выходы модели | По умолчанию 20, максимум 50 |
| `calculate_statistics` | Агрегаты успешных строк | По умолчанию 100, максимум 500 |
| `explain_statistic` | Проверка median/mean по наблюдениям | До 500 строк/ID |

Общие фильтры: `experiment_key`, `approach`, `backend`, `model_name`,
`run_index`. Имя модели передаётся точно как в БД; отображаемое название
с добавленным бэкендом не является именем модели.

## 4. Словарь метрик

| Ключ | Представление | Ограничение интерпретации |
|---|---|---|
| `inference_ms` | Инференс, мс | Не обязательно полное время сценария |
| `first_token_ms` | Первое предсказание, мс | Для разных задач точка измерения различается |
| `load_ms` | Загрузка модели, мс | Кэшированная модель может дать ноль |
| `total_ms` | Полное время, мс | Бери записанное значение, не сумму догадок |
| `memory_mb` | Память JS heap, МБ | Не измерение VRAM или всей памяти процесса |

## 5. Формулы и происхождение результата

Для отсортированных `x₁ ≤ … ≤ xₙ`:

- **Нечётное n:** медиана = `x[(n + 1) / 2]`.
- **Чётное n:** медиана = `(x[n / 2] + x[n / 2 + 1]) / 2`.
- **Среднее:** `(x₁ + … + xₙ) / n`.

Это описание работы инструмента, а не поручение языковой модели считать числа.
Значения и итог должны прийти из `explain_statistic`.

Новые статистические ответы сохраняют ID выборки и фильтры. При изменении или
удалении записей повторная проверка может отличаться; не обещай неизменность
старого результата без подтверждения исходных наблюдений.

## 6. Формат ответа

Сводка: **модель · бэкенд · серия, если задана** → метрика, статистика, единицы, n.
Объяснение: **значения → формула → результат → ID и серии → источник**.

Не выводи все отдельные строки, когда нужна короткая сводка. Не скрывай строки,
когда пользователь спрашивает, по каким измерениям получен результат.

## 7. Контрольные ситуации

| Ситуация | Правильное поведение |
|---|---|
| n=5 при limit=100 | Назвать пять значений, а не сто прогонов |
| Есть ошибка модели | Прочитать ошибку отдельно, не включать в статистику |
| Загрузка отсутствует | Сообщить о пропуске, не подставлять ноль |
| Есть модель, но неверный фильтр | Проверить фильтр, не объявлять всю БД пустой |
| Одна задержка значительно выше | Описать наблюдение без выдуманной причины |
| Запрошен P95 | Объяснить отсутствие показателя в инструменте |

## 8. Финальный контроль

- [ ] Эксперимент и фильтры разрешены точно.
- [ ] Не смешаны группы и разные метрики.
- [ ] n взято из samples, а не limit.
- [ ] Пропуски, ошибки и truncated обозначены.
- [ ] Формула подтверждена исходными строками при соответствующем запросе.
