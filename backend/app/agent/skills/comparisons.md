# Compare recorded series: сравнение серий

## 1. Назначение

Покажи, как изменились записанные показатели между двумя сериями.
Сравнение серий отличается от сравнения разных моделей внутри одной выборки:
для второго используй статистику, а не `compare_series`.

## 2. Обязательный протокол выполнения

<!-- runtime:start -->
Для сравнения двух серий используй compare_series.
Разреши experiment_key; first_run/second_run передай, если названы номера.
Без номеров инструмент выбирает две последние записанные серии.
Не передавай run_index вместо пары и не выдумывай отсутствующую серию.

Сопоставляются только одинаковые approach/model/backend.
Используй готовые changes: inference_before_ms, inference_after_ms,
delta_ms, delta_percent, first_samples, second_samples.
Разница second минус first: положительная задержка — медленнее,
отрицательная — быстрее. Не пересчитывай проценты языковой моделью.
Если исходное значение ноль, процент может отсутствовать.

Пустой changes означает отсутствие сопоставимых групп, не нулевую разницу.
Одна серия недостаточна. Обозначь available_series и truncated.
Одинаковое имя модели не гарантирует одинаковые входы, устройство и все настройки.
Не заявляй причинность или статистическую значимость по двум агрегатам.

Ответ: модель/бэкенд, номера серий, медиана до → после, абсолютная и доступная
относительная разница, n обеих серий, источник и ограниченный данными вывод.
[1], [2] — номера источников, не серий.
<!-- runtime:end -->

## 3. Входные параметры

| Параметр | Значение |
|---|---|
| `experiment_key` | Точный ключ одного эксперимента |
| `first_run`, `second_run` | Номера исходной и сравниваемой серий |
| `approach`, `model_name`, `backend` | Только запрошенные фильтры |
| `limit` | До 500 строк каждой выбранной серии |

Номера серий не являются ID отдельных измерений.
Не заменяй их номерами источников ответа или страниц таблицы.

## 4. Пошаговое сравнение

1. Разреши эксперимент и пару серий.
2. Получи результат `compare_series`.
3. Проверь, что серии разные и обе существуют.
4. Проверь наличие сопоставимых групп.
5. Передай числовые изменения без смены направления.
6. Укажи количество наблюдений в обеих сериях.
7. Заверши практическим выводом только для сравниваемых групп.

## 5. Интерпретация изменений

| Результат | Корректная формулировка |
|---|---|
| `delta_ms > 0` | Медианная задержка выросла |
| `delta_ms < 0` | Медианная задержка снизилась |
| `delta_ms = 0` | Медианы совпали |
| `delta_percent = null` | Процент не определён, доступна абсолютная разница |
| `changes = []` | Сопоставимых групп нет |

Разница в задержке не является разницей качества ответа.
Равные медианы не означают одинаковые распределения или одинаковые отдельные прогоны.

## 6. Шаблон результата

```text
Модель · бэкенд:
Серия A: медиана … мс → серия B: медиана … мс.
Разница: … мс (… %); задержка выросла/снизилась/не изменилась.
Количество значений: nA → nB. [источник]
```

Числа в шаблон вставляй из инструмента; это не сохранённый результат стенда.

## 7. Недостаточные данные

- Одна серия: назови доступные номера и предложи выполнить вторую.
- Разные модели: объясни отсутствие сопоставимости, не склеивай группы.
- Ограниченная выборка: укажи, что часть строк не участвовала.
- Неизвестные настройки: не приписывай изменение конкретному бэкенду или оптимизации.

## 8. Финальный контроль

- [ ] Сравнены нужные две серии одного эксперимента.
- [ ] Сопоставлены одинаковые группы.
- [ ] Знак изменения трактован правильно.
- [ ] n и ограничение выборки сохранены.
- [ ] Не заявлена значимость или причина без доказательств.
