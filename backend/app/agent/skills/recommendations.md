# Recommendation table: рекомендации с подтверждением

## 1. Назначение и режимы

Различай пересказ таблицы, совет по таблице и выбор технологии с учётом замеров.
Каждый режим имеет свою доказательную основу. Пользователь должен понимать,
какая часть ответа взята из таблицы, а какая подтверждается экспериментом.

## 2. Обязательный протокол выполнения

<!-- runtime:start -->
На вопрос о таблице вызывай read_recommendations.
Неизвестный rec_key не угадывай: прочитай таблицу и найди строку по title/comment.
Передай критерий, tfjs_verdict, gemini_verdict и комментарий.
Не приписывай таблице времена из измерений.

«На основе таблицы и последних измерений» требует ОБОИХ источников,
даже без слова «сравни»: read_recommendations, затем calculate_statistics.
Определи experiment_key по комментарию нужного критерия и каталогу.
Не бери эксперимент из прошлой темы, если текущий критерий указывает на другой.
Не останавливайся после таблицы и не повторяй её вместо получения статистики.

Начни с выбора для названной задачи, затем вердикт таблицы, реальные метрики
модели/бэкенда с единицами и n, условия рекомендации. Цитируй оба источника.
Сравнивай одинаковые метрики: загрузка, первый результат и полное время различаются.
Скорость классификации не доказывает скорость генерации.
ONNX не называй TensorFlow.js из-за исторического approach.

Если измерений нет, обозначь качественную основу и отсутствие количественного
подтверждения. Расхождение с таблицей покажи без выдуманной причины.
Не объявляй универсального победителя по маленькой локальной выборке.

## 3. Карта источников

| Часть ответа | Источник | Что сохранять |
|---|---|---|
| Содержание критерия | `read_recommendations` | Название и точный смысл вердиктов |
| Фактическая скорость | `calculate_statistics` | Метрика, модель, бэкенд, n |
| Область применимости | Оба источника | Задача и условия сохранённой выборки |

`rec_key` идентифицирует строку таблицы; `experiment_key` — эксперимент.
Они могут различаться. Например, критерий `text_speed` связан с экспериментом
`text_classification`; связь должна быть подтверждена актуальным комментарием.

## 4. Пошаговый сценарий смешанного запроса

1. Выдели критерий пользователя: скорость, память, доступность, управление бэкендом.
2. Прочитай релевантную строку таблицы.
3. Найди связанный эксперимент по комментарию и каталогу.
4. Получи агрегаты без дополнительных неподтверждённых фильтров.
5. Сопоставь содержание вердикта с измеренными показателями.
6. Сформулируй выбор и условия, при которых он применим.
7. Проверь ссылки на оба источника и ограничения данных.

## 5. Формат результата

Рекомендуемый порядок:

1. **Выбор:** технология и задача, для которой совет обоснован.
2. **Таблица:** качественный аргумент для обеих парадигм.
3. **Измерения:** конкретная метрика, модель/бэкенд, значение и n.
4. **Ограничение:** что данные не позволяют утверждать.

Не дублируй всю таблицу. Если пользователь спрашивает только её содержание,
не добавляй экспериментальные числа по собственной инициативе.

## 6. Расхождения и неполная проверка

Таблица может описывать общий компромисс, а замеры — конкретное устройство.
Различие само по себе не доказывает ошибку таблицы.
При отсутствии метрики не подменяй её похожей: память JS heap не равна полной памяти.
При `truncated` обозначь ограничение выборки.
Если подходящего критерия нет, назови ближайшие доступные строки без выдуманного вердикта.

## 7. Контрольные ситуации

| Ситуация | Ожидаемое поведение |
|---|---|
| «Что сказано про скорость текста?» | Прочитать строку таблицы, сохранить оба вердикта |
| «Посоветуй по таблице и замерам» | Получить два источника |
| Ранее обсуждался поиск, теперь скорость классификации | Переключить эксперимент по текущему критерию |
| Замеров нет | Качественный совет с явным ограничением |
| Таблица и числа расходятся | Разделить источники, не изобретать объяснение |

## 8. Финальный контроль

- [ ] Критерий найден в актуальной таблице.
- [ ] Связанный эксперимент подтверждён.
- [ ] Оба запрошенных источника прочитаны.
- [ ] Числа не приписаны таблице.
- [ ] Вывод относится к названной задаче и выборке.
