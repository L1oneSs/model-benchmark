# Агент стенда

`service.py` обрабатывает запрос, собирает доказательства через `planner.py`,
формирует ответ через Ollama (`OLLAMA_CHAT_MODEL`) и отдаёт NDJSON.
`history.py` хранит до 30 пар вопрос/ответ в БД.

## Инструменты

| Модуль в `tools/` | Инструменты |
|---|---|
| `recommendations.py` | `read_recommendations`: текущая статичная таблица |
| `measurements.py` | `list_experiments`, `read_measurements`: каталог и отдельные прогоны |
| `statistics.py` | `calculate_statistics`, `compare_series`: статистика и сравнение серий |
| `statistics.py` | `explain_statistic`: формула медианы/среднего и исходные значения с ID/сериями |
| `charts.py`, `../chart_rendering.py` | `build_chart`: HTML/CSS, Python PNG или интерактивный Plotly; медиана/среднее |
| `schemas.py`, `__init__.py` | Pydantic-аргументы, ограничения и реестр |

Запросы к БД параметризованы. Инструментов произвольного SQL, выполнения кода,
записи или запуска браузерных экспериментов нет. Планировщик допускает
четыре шага и до восьми вызовов инструментов.
Выборка статистики ограничена 500 успешными прогонами.
Пропущенные метрики не превращаются в ноль. Группы разных моделей не смешиваются.

## Инструкции по сценариям

Файлы `skills/core.md`, `answer.md`, `recommendations.md`, `measurements.md`,
`comparisons.md`, `charts.md` реально читаются приложением. `skills/__init__.py`
подгружает инструкции доступных инструментов в планировщик. Для прямых вопросов
о таблице, статистике, сравнении серий и графиках инструменты ограничиваются
нужным сценарием. Запрос «на основе таблицы и измерений» требует оба инструмента:
`read_recommendations` и `calculate_statistics`; план не может завершиться после
получения только одного источника. Для остальных общих вопросов доступен весь набор.

Это инструкции собственного агента, не скиллы Codex. Они описывают
порядок работы и ограничения; выполнение обеспечивают Python-инструменты.
После изменения файлов пересоберите backend, поскольку Docker копирует их в образ.

`reports.py` выводит числовые результаты без повторной интерпретации моделью.
Графики возвращаются как типизированные данные в `charts`, отображаются клиентом
и сохраняются вместе с ответом. HTML/SVG/код от модели не исполняется.
Запрос «по всем метрикам» задаёт `metric=all`: отдельные графики инференса,
первого предсказания, загрузки, полного времени и памяти JS heap; отсутствующие
измерения явно перечисляются, а не заменяются нулями.

## API и совместимость

Для вопросов о формуле планировщик восстанавливает эксперимент и состав выборки
из источников предыдущего ответа, затем перечитывает измерения. Новые статистические
ответы сохраняют ID выбранных строк и фильтры. Старые ответы без этой информации
проверяются по текущим данным с явным предупреждением. История используется для
определения выборки, а сами значения подтверждаются БД.

Основной API — `/api/agent/ask`, `/api/agent/history`, `/api/agent/history/import`.
UUID чата передаётся в `X-Agent-Chat`. Старые `/api/rag` адреса чата и заголовок
`X-Rag-Chat` временно принимаются тем же агентом и скрыты из Swagger.
Переиндексации больше нет: `/api/rag/reindex` возвращает 404.

Имя существующей таблицы `rag_chats` и ключ UUID в localStorage сохранены,
чтобы не потерять историю. Старый `rag_documents` в существующей БД может остаться
неиспользуемой таблицей; приложение её не читает и не создаёт в новой установке.
## Форматы графиков

`build_chart` принимает `renderer`: `html` (график в чате), `python_static`
(Matplotlib → PNG), `python_interactive` (Plotly → самостоятельный HTML с наведением,
масштабированием и экспортом). `statistic`: `median` или `mean`; `metric="all"`
строит отдельный график каждой доступной метрики. Все форматы используют одинаковые
группы и успешные измерения. Тип диаграммы пока горизонтальный столбчатый.
Интерактивность не означает live-обновление данных.

Python выполняет только доверенные шаблоны рендеринга, не код из ответа модели.
Файлы сохраняются в `artifacts/agent-charts`, Docker монтирует эту папку с хоста.
Ссылки `/api/agent/charts/{uuid}.png|html` сохраняются в истории чата; удаление
папки делает старые файловые ссылки недоступными. Автоматического удаления файлов нет.
Это локальный стенд: ссылки с непредсказуемым UUID доступны без авторизации.
Интерактивные файлы включают Plotly.js и не требуют CDN; клиент открывает их
в iframe с `sandbox="allow-scripts"`. Размер HTML может составлять несколько МБ.

Скиллы `core`, `answer`, `measurements`, `recommendations`, `comparisons`, `charts`
содержат YAML-описание, назначение, алгоритм, параметры, трактовку данных,
примеры, контрольные ситуации и чек-лист результата. Для планирования загружается
обязательный протокол между `runtime:start` и `runtime:end`: все рабочие правила,
без повторяющихся справочных таблиц и учебных шаблонов. Это сохраняет место для
данных и схем инструментов в контексте локальной модели. `answer` загружается
целиком в финальный ответ. `gost-bibliography-skill.md` — предоставленный образец,
не подключённый к инструментам стенда сценарий.
Изменение файлов требует перезапуска/пересборки контейнера из-за кеширования инструкций.
