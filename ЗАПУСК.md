# Как запустить стенд и снять свои замеры

Инструкция для того, кто открывает проект впервые. Ничего программировать не нужно,
всё сводится к одной команде и трём кнопкам.

## Шаг 1. Установить Docker Desktop

Скачать с <https://www.docker.com/products/docker-desktop/>, установить, запустить.
Дождаться, пока значок кита в трее перестанет мигать — это значит, что Docker готов.

Больше ничего ставить не нужно: ни Python, ни Node.js. Всё остальное приложение
привезёт с собой.

## Шаг 2. Запустить стенд

**Windows:** двойным щелчком открыть файл `ЗАПУСТИТЬ.bat` в папке проекта.

**macOS или Linux:** открыть терминал в папке проекта и выполнить `bash run.sh`.

Если привычнее вручную — в той же папке выполнить:

```
docker compose up -d --build
```

Первый запуск долгий: качаются образы и две языковые модели для чат-бота,
суммарно около 3,2 ГБ. Это от нескольких минут до получаса в зависимости от
канала. Последующие запуски занимают секунды.

Когда всё поднимется, открыть в браузере <http://localhost:8080>.

## Шаг 3. Проверить среду

Первое, что видно на вкладке «Стенд», — панель **Среда прогона**. В ней указаны
версия браузера, видеоадаптер и таблица встроенных ИИ-API.

Нажать **«Записать в датасет»**. Эта кнопка сохраняет конфигурацию машины
в результаты. Без неё замеры не с чем будет сопоставить: числа с разных
компьютеров сравнимы только вместе с описанием железа.

Строка над таблицей сразу скажет, доступна ли на этой машине встроенная модель.
Если написано, что недоступна, это не поломка — это результат. Стенд продолжит
работать, просто колонка Gemini Nano останется незаполненной.

## Шаг 4. Прогнать эксперименты

Ниже панели среды — три карточки. В каждой поле ввода, кнопка **«Запуск»** и
свёрнутый блок с последним результатом.

Нажать «Запуск» по очереди во всех трёх. Порядок значения не имеет.

**Вкладка должна оставаться активной.** Если свернуть окно или уйти на другую
вкладку, браузер задушит рендеринг и замеры собьются. Стенд это отслеживает и
откажется стартовать в фоне, но во время прогона лучше просто не трогать окно.

Каждый прогон — серия из шести измерений: первое отбрасывается как прогревочное,
по остальным считаются медиана и разброс. Занимает от нескольких секунд до пары
минут на карточку.

## Шаг 5. Забрать результаты

Вкладка **«Измерения»** — сводка по каждому эксперименту и список последних
прогонов. Ссылка **«Выгрузить CSV»** скачивает весь датасет одним файлом.

Этот CSV и есть то, что нужно прислать обратно. В нём уже лежит всё: конфигурация
машины, версия браузера, видеоадаптер, все метрики по каждому прогону.

## Шаг 6. Остановить

**Windows:** двойным щелчком `ОСТАНОВИТЬ.bat`.
Иначе — `docker compose down` в папке проекта.

Данные сохранятся: при следующем запуске все прогоны будут на месте.
Чтобы стереть базу и начать с чистого листа — `docker compose down -v`.

## Если что-то пошло не так

**Порт занят.** Скопировать `.env.example` в `.env` и поменять `FRONTEND_PORT`
на свободный, например 8081. Перезапустить.

**Windows сообщает `bind: ... forbidden by its access permissions`.**
Порт может быть зарезервирован Windows, даже если ни один процесс его не слушает.
Посмотреть резерв: `netsh interface ipv4 show excludedportrange protocol=tcp`.
Выберите порты вне этих диапазонов и укажите в `.env`, например:

```dotenv
BACKEND_PORT=18000
FRONTEND_PORT=18080
VITE_API_BASE_URL=http://localhost:18000
CORS_ORIGINS=http://localhost:18080
```

После изменения выполните `docker compose up -d --build`, чтобы фронтенд
получил новый адрес API. В этом примере интерфейс доступен на
<http://localhost:18080>, API — на <http://localhost:18000>.

**Чат-бот отвечает, что модель недоступна.** Языковые модели ещё качаются.
Посмотреть ход загрузки: `docker compose logs -f llm-bootstrap`. Эксперименты
при этом уже работают, ждёт только бот.

**Страница не открывается.** Проверить, что Docker Desktop запущен, и посмотреть
`docker compose ps` — все сервисы должны быть в состоянии running или healthy.

**Эксперимент с изображением падает.** Кнопка «Выбрать своё изображение» в
карточке позволяет подставить любую фотографию с диска вместо встроенного
тестового паттерна.

## Как независимо проверить числа стенда

Результаты стенда можно сверить с официальным инструментом TensorFlow.js от Google.
Ни Docker, ни этот проект для этого не нужны — только браузер.

1. Открыть <https://tensorflow.github.io/tfjs/e2e/benchmarks/local-benchmark/>.
2. В панели справа выбрать `models` → **MobileNetV2**, `architecture` → **100**
   (это множитель ширины 1,0, как в стенде).
3. Выбрать `backend`: **webgl**, **webgpu**, **wasm** или **cpu**.
4. Нажать **Run benchmark** и не уходить с вкладки до конца прогона.
5. Сравнить строку среднего времени инференса с медианой на вкладке «Измерения» стенда.

Совпадения до миллисекунды ждать не стоит, и это ожидаемо. Инструмент Google подаёт
на вход случайный тензор и меряет чистый вызов модели, а стенд классифицирует
настоящее изображение и включает в замер предобработку кадра и выбор трёх лучших
классов. Порядок величин и соотношение бэкендов между собой должны совпадать —
именно это и подтверждает корректность методики.

Для текстового эксперимента в том же инструменте есть модель **USE - batchsize 1** —
тот же Universal Sentence Encoder, что использует стенд.
