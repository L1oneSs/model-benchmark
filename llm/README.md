# llm — локальная модель агента

Ollama запускается сервисом `llm`, а `llm-bootstrap` скачивает только чат-модель
`qwen3.5:4b`. Модель задаётся `OLLAMA_CHAT_MODEL` в `.env`. Эмбеддинги и векторный
индекс удалены; ранее скачанные веса автоматически не удаляются.

Образ сервиса `ollama/ollama` берётся из Docker Hub, а веса модели — из каталога
Ollama. Модель работает локально: внешние API и ключи для чата не нужны.
Выбран вариант 4B с учётом лимита памяти контейнера; более крупные варианты
нужно отдельно проверять по памяти и времени ответа.

```sh
docker compose logs -f llm-bootstrap
docker compose exec llm ollama list
```

Между контейнерами Ollama доступна на `http://llm:11434`, с ноутбука — на
`http://localhost:11434`; внешний порт задаётся `OLLAMA_PORT`.

Планировщик выбирает инструменты структурированным JSON-планом. Инструкции
подгружаются из `backend/app/agent/skills/`. Инструменты читают PostgreSQL напрямую.
Числовые отчёты и данные графиков формирует Python; свободные объяснения — Ollama.
Thinking относится к свободным объяснениям, а не к числовым отчётам.

Ограничения контейнера: 5 ГБ памяти, четыре CPU, одна загруженная модель и один
параллельный запрос. GPU в Compose не настроен. `OLLAMA_KEEP_ALIVE=0` выгружает
модель после запроса, уменьшая удерживаемую память, но добавляя время загрузки.
Контекст — 8192 токена; длина ответа задаётся `AGENT_MAX_TOKENS` (384
по умолчанию), старое имя `RAG_MAX_TOKENS` временно поддерживается.

Для смены модели задайте `OLLAMA_CHAT_MODEL`, затем пересоздайте bootstrap и backend:

```sh
docker compose up -d --force-recreate llm-bootstrap backend
```

Модель должна поддерживать структурированный формат Ollama. Качество
выбора инструментов и время ответа проверяются на вопросах стенда.
