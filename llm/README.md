# llm — Ollama для RAG-бота

Ollama обслуживает серверный чат и векторизацию источников. Она не исполняет экспериментальные модели TF.js/ONNX и не заменяет Gemini Nano в Chrome. После скачивания весов ответы генерируются локально; первоначальная загрузка обращается к реестру Ollama.

## Модели и загрузка

| Назначение | Значение по умолчанию | Переменная |
|---|---|---|
| Ответы RAG | `qwen3:4b` | `OLLAMA_CHAT_MODEL` |
| Эмбеддинги | `qwen3-embedding:0.6b` | `OLLAMA_EMBEDDING_MODEL` |

Веса сохраняются в Docker-томе `ollama`. Сервис `llm-bootstrap` ждёт готовности Ollama, проверяет `ollama list`, скачивает отсутствующие модели через `ollama pull` и завершается. Повторный запуск использует уже скачанные модели. Оценка размера двух стандартных загрузок — несколько гигабайт; фактический объём зависит от тегов моделей.

```sh
docker compose logs -f llm-bootstrap
docker compose exec llm ollama list
```

`backend` зависит от healthcheck Ollama, а не от завершения bootstrap. Поэтому готовый интерфейс/API ещё не гарантирует готовность RAG-бота. Ошибки загрузки смотрите в логах bootstrap.

Для замены задайте имена моделей в корневом `.env` и выполните:

```sh
docker compose up -d llm-bootstrap backend
```

После смены embedding-модели нужен заново сформированный совместимый индекс: старые векторы рассчитаны другой моделью. Текущее обновление индекса сравнивает текст документов, а не имя embedding-модели, поэтому одной команды `/reindex` для неизменившихся документов недостаточно. Очистите `rag_documents`, затем вызовите `POST /api/rag/reindex`. Измерения и рекомендации при этом можно сохранить.

## Ресурсы и задержки

Compose ограничивает Ollama 5 ГБ памяти без дополнительного swap, четырьмя CPU, одной загруженной моделью и одним параллельным запросом. GPU в текущей конфигурации не выделяется.

Бэкенд использует контекст 4096 токенов, четыре потока и `RAG_MAX_TOKENS=384` по умолчанию. `OLLAMA_KEEP_ALIVE=0` выгружает чат-модель после ответа; эмбеддинги запрашиваются также с `keep_alive: 0`. Это уменьшает удерживаемую память, но добавляет загрузку модели к следующим запросам. Скорость зависит от устройства, поиска и длины контекста; фиксированное время ответа не гарантируется.

В логах backend видны время поиска, загрузки и общее время ответа. Полный поток можно измерить [чекером RAG](../checks/README.md).

## Thinking

Пользователь переключает Thinking в поле ввода RAG. Backend передаёт Ollama `think`, запрашивает структурированный JSON с полем `answer`, передаёт рассуждения отдельными событиями и сохраняет их отдельно. При thinking бюджет увеличивается на 512 токенов. Если рассуждения исчерпали бюджет без ответа, выполняется дополнительный запрос без thinking.

Текущая реализация не обещает автоматический повтор без параметра `think` для любой несовместимой модели. При смене чат-модели проверяйте поддержку параметров и структурированного ответа.

## Адреса и проверка

Другие контейнеры обращаются к `http://llm:11434`. На ноутбуке по умолчанию опубликован `http://localhost:11434`; внешний порт меняется через `OLLAMA_PORT`.

```sh
curl http://localhost:11434/api/tags
curl http://localhost:11434/api/chat -H 'Content-Type: application/json' -d '{"model":"qwen3:4b","stream":false,"think":false,"messages":[{"role":"user","content":"Привет"}]}'
```

Для GPU NVIDIA потребуется настройка доступа контейнера к устройству и поддержка драйверов в среде Docker. Это ускоряет только серверный RAG, а не браузерные эксперименты. Более крупная модель также потребует пересмотреть текущий лимит памяти.

`docker compose down` сохраняет веса. `docker compose down -v` удаляет их вместе с томом PostgreSQL.
