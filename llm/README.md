# llm — локальная языковая модель

Ollama в контейнере. Ни одного обращения к внешним API: модели скачиваются один
раз при первом запуске и живут в томе `ollama`.

## Две модели

| Роль        | Модель по умолчанию      | Размер  | Зачем                                            |
|-------------|--------------------------|---------|--------------------------------------------------|
| генерация   | `qwen3:4b`               | ~2,5 ГБ | ответы RAG-бота                                   |
| эмбеддинги  | `qwen3-embedding:0.6b`   | ~640 МБ | векторизация рекомендаций, измерений и вопросов   |

Qwen3 4B помещается в 4 ГБ оперативной памяти, поддерживает больше сотни языков
и доступна в библиотеке Ollama одной командой. Модели на 8 и более миллиардов
параметров отвечают заметно лучше, но требуют около 8 ГБ и на типичном ноутбуке
ощутимо задумываются.

Эмбеддинги взяты из того же семейства: Qwen3-Embedding 0.6B весит всего 640 МБ,
работает со 100+ языками и делит токенизацию с генеративной моделью. Русские
формулировки вопроса и русский текст рекомендаций попадают в одно векторное
пространство — англоязычный энкодер здесь давал бы заметно худший поиск.
Предыдущий кандидат `bge-m3` тоже мультиязычный, но вдвое тяжелее при сопоставимом
качестве на таком маленьком корпусе.

### Режим рассуждений

Qwen3 умеет рассуждать вслух и по умолчанию возвращает ход мыслей вместе с
ответом. Бэкенд просит его отключить (`"think": false` в запросе к Ollama), а на
случай, если модель всё же вернёт блок `<think>`, ответ дополнительно чистится
регулярным выражением. Если выбранная модель флага не понимает, запрос
автоматически повторяется без него.

Замена — через `.env`, перезапуск подтянет новые модели автоматически:

```env
OLLAMA_CHAT_MODEL=qwen3:8b
OLLAMA_EMBEDDING_MODEL=bge-m3
```

## Как устроена загрузка

Сервис `llm` поднимает Ollama, одноразовый `llm-bootstrap` дожидается её
готовности и вызывает `ollama pull` для обеих моделей, после чего завершается.
Уже скачанные модели пропускаются, так что повторный запуск стенда мгновенный.

Прогресс: `docker compose logs -f llm-bootstrap`.

Первая загрузка занимает от нескольких минут до получаса, зависит от канала.
Суммарно качается около 3,2 ГБ.
Пока она идёт, стенд работает: эксперименты прогоняются и сохраняются, недоступен
только чат с ботом.

## Проверка

```bash
docker compose exec llm ollama list
curl http://localhost:11434/api/tags
```

Прямой вопрос модели, минуя стенд:

```bash
curl http://localhost:11434/api/chat -d '{
  "model": "qwen3:4b",
  "stream": false,
  "messages": [{"role": "user", "content": "Привет"}]
}'
```

## Видеокарта

По умолчанию Ollama считает на процессоре: так стенд запускается на любой
машине. Ответ на вопрос занимает несколько секунд — для консультанта этого
достаточно.

Чтобы задействовать видеокарту NVIDIA, добавьте сервису `llm` в
`docker-compose.yml`:

```yaml
    deploy:
      resources:
        reservations:
          devices:
            - driver: nvidia
              count: all
              capabilities: [gpu]
```

Нужен установленный NVIDIA Container Toolkit. На скорость самих экспериментов
это не влияет никак: они считаются в браузере, а не здесь.
