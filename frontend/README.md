# frontend — интерфейс стенда

React 19 на TypeScript 7, стили на SCSS, сборка Vite 8, раздача nginx.
Здесь же выполняются **все замеры**: обе сравниваемые парадигмы работают в
браузере, поэтому фронтенд — не витрина, а измерительный инструмент.

## Структура

```
src/
```

## Три вкладки

**Стенд.** Сверху панель среды: версия браузера, видеоадаптер, состояние
вкладки и таблица встроенных ИИ-API с их доступностью. Кнопка «Записать в
датасет» сохраняет эту диагностику в общую таблицу измерений — на машине без
подходящего железа это и есть первый результат эксперимента. Ниже параметры
серии и карточка на каждый эксперимент: поле ввода, кнопка «Запуск» и
сворачиваемый блок с результатом последнего измерения.

**Измерения.** По каждому эксперименту сводка в разрезе парадигм (медиана,
разброс, число прогонов) и постраничный список последних запусков по пять штук.
Оттуда же выгружается CSV.

**Рекомендации.** Два под-таба: статичная таблица вердиктов по критериям и
RAG-бот, который отвечает по этой таблице и свежим измерениям.

## Адаптер TensorFlow.js

`models/tensorflow.ts`. Модели кешируются в модуле: без этого каждый прогон
мерил бы сеть, а не инференс. Время первой загрузки записывается отдельной
метрикой `load_ms`.

Классификация текста устроена так: опорные фразы («отличный продукт» /
«ужасный продукт») кодируются энкодером один раз при загрузке, дальше в
латентность попадает только кодирование входного текста и два скалярных
произведения. Классификация изображений — MobileNet v2, топ-1 класс ImageNet.

Бэкенд WebAssembly поставляется отдельным пакетом `@tensorflow/tfjs-backend-wasm`
и без явной регистрации не виден библиотеке: `tf.findBackend('wasm')` возвращает
пустоту, и эксперимент молча его пропускает. Адаптер регистрирует его при первом
обращении, а двоичные модули `.wasm` копируются в `public/wasm/` на этапе сборки
образа, так что стенд раздаёт их сам.

Эксперимент со сменой ускорителя перезагружает модель после каждого
переключения: смена бэкенда обесценивает скомпилированные ядра, и без
перезагрузки числа получились бы несопоставимыми.

## Адаптер Gemini Nano

`models/geminiNano.ts`. Состояние API на сентябрь 2026: для веба он стабилен
начиная с Chrome 148 и живёт в глобальном `LanguageModel`, флаги не нужны.
В расширениях доступен с Chrome 138. В сборках до 138-й API лежал в
`window.ai.languageModel` с методом `capabilities()` — адаптер понимает и эту
форму и приводит ответы к единому набору статусов, поэтому стенд запускается и
на машине с отстающим браузером.

Два ограничения API прямо влияют на методику.

**Язык.** Prompt API принимает `en`, `ja`, `es`, `de` и `fr`. На русский вход
браузер отвечает `NotSupportedError`. Сравнительные прогоны поэтому идут на
английском: иначе сравнивались бы не парадигмы, а наличие языка в списке
поддерживаемых. Universal Sentence Encoder тоже обучен на английском, так что
условия равные. Если в поле ввода оказалась кириллица, карточка эксперимента
предупреждает об этом заранее, но прогон не блокирует — отказ записывается
статусом `unsupported` и становится самостоятельным наблюдением.

**Параметры модели.** `temperature` и `topK` отдали только расширениям, на вебе
их выставить нельзя. Сессия создаётся со значениями по умолчанию, и в настройках
прогона это записано прямым текстом — чтобы числа не выглядели снятыми при
произвольной температуре.

Доступность проверяется с объявлением ожидаемых модальностей:
`availability({expectedInputs, expectedOutputs})`. Для эксперимента с
изображением в `expectedInputs` добавляется `{type: 'image'}` — так браузер
заранее говорит, потянет ли он мультимодальный вход.

Время до первого предсказания снимается через `promptStreaming()` по первому
фрагменту потока — это прямой аналог метрики из теоретической части. Метод
возвращает `ReadableStream`, который в Chrome работает как асинхронный итератор.
Если потоковый режим недоступен, метрика приравнивается к полному времени ответа.

Недоступность модели не считается сбоем: прогон записывается со статусом
`unsupported` и текстом причины. Для экспериментальной главы это такой же
результат, как и число.

## Разработка без Docker

Нужен Node 20.19+ или 22.12+ — это требование Vite 8.

```bash
npm install --legacy-peer-deps
npm run dev          # http://localhost:5173
npm run typecheck
npm run build
```

Vite 8 собирает через Rolldown, и он принимает `manualChunks` только функцией:
объектная форма, привычная по Vite 5, приводит к ошибке
`manualChunks is not a function`. В `vite.config.ts` используется функция.

`--legacy-peer-deps` обязателен: пакет `universal-sentence-encoder` объявляет
peer-зависимость на TensorFlow.js 3.x, тогда как `mobilenet` требует 4.x.
Установка сводит дерево к единственной копии `tfjs-core` 4.22.0, и обе модели
работают через стабильный API `loadGraphModel`. Это ограничение экосистемы,
а не проект: поддерживаемых текстовых моделей под TensorFlow.js 4.x попросту
нет, и сам по себе этот факт стоит упомянуть в выводах.

## Переменные сборки

| Переменная            | Значение                                                   |
|-----------------------|------------------------------------------------------------|
| `VITE_API_BASE_URL`   | адрес бэкенда, по умолчанию `http://localhost:8000`        |
| `VITE_MODEL_SOURCE`   | `cdn` (по умолчанию) или `local` — веса из `public/models` |

Подставляются на этапе сборки образа, поэтому после смены нужен
`docker compose up -d --build frontend`.


## Почему запуск блокируется в фоновой вкладке

`runner.ts` проверяет `document.visibilityState` и выбрасывает `HiddenTabError`,
если вкладка не активна. Ограничение выяснилось опытным путём: при неактивной
вкладке Chrome душит рендеринг, и прогон MobileNet на бэкенде WebGL не
завершается за две с лишним минуты, тогда как WebGPU в тех же условиях отдаёт
нормальную медиану. Смешивать такие числа в одном датасете нельзя, поэтому
состояние вкладки попадает в описание среды каждого измерения, а запуск в фоне
не разрешается вовсе.
