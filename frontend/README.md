# frontend — интерфейс и браузерные измерения

React 19, TypeScript 7, SCSS, Vite 8. Production-сборку раздаёт nginx. Экспериментальный инференс выполняется в браузере через TensorFlow.js, Transformers.js / ONNX Runtime Web или встроенные ИИ-API Chrome. Чат агента обращается к отдельному серверному API.

## Стенд и результаты

Каждая карточка хранит собственный выбор моделей/бэкендов, число повторов и настройку прогрева. «Запустить все» последовательно запускает карточки с их текущими входами и настройками. Для ONNX нет выбора ускорителей TF.js; библиотечную модель можно отключить независимо от встроенного подхода.

QnA использует отдельные поля вопроса и контекста. В семантическом поиске — отдельный запрос, до пяти документов с фиксированными буквами, названиями и текстом до 250 символов. Перевод поддерживает en ↔ ru и фильтрацию букв исходного языка. В генерации применяется маска английского ввода.

Последний результат находится в сворачиваемом блоке карточки. Полная история — на вкладке «Измерения», по пять записей на странице. Фильтр бэкенда показывается для TF.js при выборе библиотечной или всех парадигм. `tfjs_backends` выводит парадигму, настройки, инференс и дату, а сводка включает модель и медиану по бэкенду.

CSV в карточке выгружает весь соответствующий эксперимент, общая кнопка — весь датасет. Фильтры списка не передаются в экспорт. Диагностика `builtin_availability` записывается из панели среды, но отдельной таблицы для неё на вкладке «Измерения» нет.

## Модели

Полная таблица экспериментов: [корневой README](../README.md#эксперименты).

TF.js использует MobileNet v2, USE lite, Toxicity, MobileBERT QnA, COCO-SSD и TF.js-реализацию BlazeFace / MediaPipe Face Detector. USE участвует в тональности, экстрактивной суммаризации и семантическом поиске. Для этих задач код определяет алгоритм работы с эмбеддингами; USE сам не генерирует текст.

ONNX-модели загружаются лениво через Transformers.js:

| Задача | Идентификатор модели |
|---|---|
| Перефразирование | `Xenova/flan-t5-small` |
| Перевод en → ru | `onnx-community/opus-mt-en-ru` |
| Перевод ru → en | `Xenova/opus-mt-ru-en` |
| Определение языка | `onnx-community/xlm-roberta-base-language-detection-ONNX` |
| Грамматика | `rabden/t5-tiny-gec-hone` |
| Генерация | `HuggingFaceTB/SmolLM2-360M-Instruct` |

Используется `dtype: q8`. Генерация имеет отдельный кеш, выполняется на WASM и использует чат-шаблон модели, лимит 100 новых токенов, `do_sample: false`, `repetition_penalty: 1.1`, `no_repeat_ngram_size: 4`. Эти ограничения снижают зацикливание, но не проверяют достоверность ответа. Остальные ONNX-пайплайны используют выбор устройства библиотеки по умолчанию.

В API/БД ONNX пока сохраняется с `approach: tensorflow_js`: это общий ключ библиотечного подхода. Название ONNX в карточках и фильтрах берётся из `libraryLabel` эксперимента. Действительную модель хранит `model_name`, параметры — `settings`.

## Кеширование и метрики

Модели кешируются в модуле, повторная загрузка даёт `load_ms: 0`. В эксперименте `tfjs_backends` MobileNet принудительно перезагружается на каждом вызове `runOnBackend`; остальные адаптеры используют свои кеши. WebGPU и WASM регистрируются до определения доступных ускорителей при открытии стенда. Двоичные модули TF.js WASM копируются в `public/wasm/` при Docker-сборке.

Исключение первого прогона опционально: при включённом чекбоксе дополнительный первый вызов не сохраняется. Он может включать загрузку и компиляцию, а не только компиляцию шейдеров. Отдельно адаптер MobileNet всегда выполняет внутренний прогрев после загрузки, независимо от чекбокса; его время включено в `load_ms`. Поэтому сводная загрузка кешированной модели часто равна нулю. Запуск серии из фоновой вкладки блокируется.

`first_token_ms` — первый фрагмент потока для потокового Prompt API; в адаптерах без потокового измерения это полное время инференса. `memory_mb` отражает JS-кучу, если браузер предоставляет её измерение, и не является памятью всех весов или GPU.

## Встроенные API

Для классификации, поиска, QnA и обработки изображений используется Prompt API. Для суммаризации, перефразирования, грамматики и генерации адаптер сначала использует специализированный API, а при его отсутствии или ошибке — Prompt API. Для перевода и определения языка используются только Translator и LanguageDetector, без подмены другим алгоритмом.

Поддержка проверяется в браузере: наличие глобального API, `availability()` и ожидаемые модальности. Изображения требуют мультимодального Prompt API. Недоступность записывается как `unsupported`, ошибка исполнения — как `error`. Адаптер также понимает старый интерфейс `window.ai.languageModel`.

Prompt-задачи настроены на английский вход. Предупреждение о кириллице относится только к соответствующим задачам; перевод и определение языка имеют отдельную обработку. Translator и LanguageDetector используют отдельные браузерные модели. Загрузка Nano отслеживается при открытии стенда; если Chrome требует действие пользователя, интерфейс предлагает запустить загрузку. Для переводов создание языкового пакета начинается из обработчика кнопки запуска.

## Чат агента

История читается и сохраняется через API. `localStorage` хранит UUID чата; поддержан импорт прежней клиентской истории. Лимит — 30 завершённых ответов. Thinking и удаление истории находятся в блоке ввода. NDJSON-события отделяют текст ответа от рассуждений и источников; незавершённый поток не выдаётся за завершённый ответ.

## Разработка и сборка

Из каталога `frontend`, Node.js 20.19+ или 22.12+:

```sh
npm install --legacy-peer-deps
npm run dev
npm run typecheck
npm run build
```

Dev-сервер: http://localhost:5173. Для текущего API задайте `VITE_API_BASE_URL=http://localhost:18000` в окружении Vite либо `frontend/.env.local`. Корневой `.env` используется Docker Compose, не подхватывается Vite автоматически из каталога frontend. Бэкенду для dev-режима потребуется `CORS_ORIGINS`, содержащий `http://localhost:5173`.

Установка использует `--legacy-peer-deps` из-за несовместимых деклараций peer-зависимостей пакетов TF.js. Сборка Vite 8 использует Rolldown и функцию `manualChunks`.

| Переменная сборки | По умолчанию | Текущее локальное значение Compose |
|---|---|---|
| `VITE_API_BASE_URL` | `http://localhost:8000` | `http://localhost:18000` |
| `VITE_MODEL_SOURCE` | `cdn` | `cdn`, если не переопределено |

`VITE_MODEL_SOURCE=local` переключает все модели TensorFlow.js: [инструкция](public/models/README.md). После смены переменных сборки выполните из корня `docker compose up -d --build --no-deps frontend`. Текущий адрес интерфейса — http://localhost:18080.

Проверочные скрипты находятся в [../checks](../checks/README.md). Изображения и их источники: [samples](public/samples/README.md).

Агент выбирает серверные инструменты чтения рекомендаций, прогонов, статистики и сравнения серий. В интерфейсе показываются этапы обращения к данным и источники; обновление векторного индекса для чата не требуется. Клиент использует `src/api/agentApi.ts` и `/api/agent/*`; старые адреса чата оставлены временными алиасами. Графики отображаются компонентом `AgentCharts.tsx` и сохраняются в истории.
## Графики агента

`AgentCharts` поддерживает HTML/CSS-диаграммы, PNG из Matplotlib и интерактивные
HTML-файлы из Plotly. Python-форматы строит бэкенд; интерфейс использует только
проверенные ссылки `/api/agent/charts/{uuid}.png|html`. Интерактивный файл открывается
в iframe с `sandbox="allow-scripts"`. Все форматы отображают медиану или среднее,
единицы измерения и фактическое число прогонов. Старые ответы без новых полей совместимы.
